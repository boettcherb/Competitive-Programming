    2018 December:
      Bronze 1: Mixing Milk
        Techniques: Simulation
        Complexity: O(1)
        Difficulty: Trivial
        Key Idea: Directly simulate the fixed sequence of 100 pours. For each
          pour, transfer min(source amount, destination remaining capacity).

      Bronze 2: The Bucket List
        Techniques: Sorting, Sweep Line (Event Processing)
        Complexity: O(N log N)
        Difficulty: Easy
        Key Idea: Convert each cow's interval into two events: +b buckets at
          the start time and -b buckets at the end time. Sort all events by
          time and sweep from left to right, maintaining the number of buckets
          currently in use. The maximum running total is the answer.

  2019-2020:
    2019 December:
      Bronze 1: Cow Gymnastics
        Techniques: Brute Force (Combination Enumeration),
          Preprocessing (Inverse Mapping)
        Complexity: O(KN^2)
        Difficulty: Easy
        Key Idea: Convert each session from "cows in ranked order" into an
          inverse lookup rankings[cow][session] = position. Then enumerate all
          pairs of cows and compare their positions across all K sessions in
          O(1) per session. A pair is consistent if the same cow is ahead in
          every session.

      Bronze 2: Where Am I?
        Techniques: Brute Force (Candidate Enumeration)
        Complexity: O(N^2) conceptually
        Difficulty: Easy
        Key Idea: Try each possible substring length K from smallest to
          largest. For a fixed K, generate every length-K substring and use a
          set to detect duplicates. The first K for which every substring is
          unique is the answer.

      Bronze 3: Livestock Lineup
        Techniques: Brute Force (Permutation Enumeration)
        Complexity: O(8! * N * 8)
        Difficulty: Easy
        Key Idea: Start with the eight cow names in alphabetical order and use
          next_permutation to enumerate lineups lexicographically. Check each
          lineup against every adjacency constraint. The first valid lineup is
          automatically the lexicographically smallest answer.

      Silver 1: MooBuzz
        Techniques: Binary Search (First True)
        Complexity: O(log N)
        Difficulty: Easy
        Key Idea: For any x, count how many integers in [1, x] are not
          divisible by 3 or 5 using inclusion-exclusion:
          count(x) = x - x/3 - x/5 + x/15. The predicate count(x) >= N is
          monotonic, so binary search for the first x for which it is true.

      Silver 2: Meetings
        Techniques: Sorting, Two Pointers (Sliding Window)
        Complexity: O(N log N)
        Difficulty: Hard
        Key Idea: Treat collisions as cows passing through each other; their
          trajectories are unchanged, while identities/weights effectively
          swap. Sort cows by position and pair left-exit trajectories with the
          leftmost cow identities and right-exit trajectories with the
          rightmost identities to determine the time T when at least half the
          total weight has exited. Then a right-moving cow at xR meets a
          left-moving cow at xL by time T iff xR < xL <= xR + 2T. Because the
          position lists are sorted, maintain moving bounds with two pointers
          to count all such pairs efficiently.

      Silver 3: Milk Visits
        Techniques: Graphs (Connected Components / Flood Fill)
        Complexity: O(N + M)
        Difficulty: Medium
        Key Idea: Flood fill through only edges whose endpoints have the same
          milk type, labeling maximal same-type connected components. If the
          endpoints of a query are in different components, their unique tree
          path crosses a type boundary and therefore contains both milk types.
          If they are in the same component, the entire path has one milk type,
          so the query succeeds only if that type matches the requested type.

      Gold 1: Milk Pumping
        Techniques: Graphs (Multi-State Shortest Path / Pareto Frontier)
          Alternative: Graphs (Dijkstra), Brute Force (Candidate Enumeration)
        Complexity: Pareto version: worst-case O(F^2 M + FM log(FM));
          standard threshold + Dijkstra: O(FM log N), where F <= M
        Difficulty: Medium
        Key Idea: A path is determined by two quantities: total cost and
          bottleneck flow. My solution keeps a Pareto frontier of nondominated
          (cost, flow) states at each node; a state is useless if another state
          reaches the same node with no greater cost and no smaller flow.
          The standard solution instead fixes a candidate minimum flow F,
          removes all edges with flow < F, and runs Dijkstra to find the
          minimum-cost remaining path. Since an optimal path's bottleneck must
          equal some edge flow, trying every distinct flow threshold finds the
          optimum ratio F / cost.

      Gold 2: Milk Visits
        Techniques: Trees (Heavy-Light Decomposition)
        Complexity: O((N + M) log^2 N)
        Difficulty: Very Hard
        Key Idea: This problem asks whether a value occurs on arbitrary tree
          paths. Use Heavy-Light Decomposition: choose each node's
          largest-subtree child as its heavy child so any u-v path breaks into
          only O(log N) contiguous heavy-chain segments. Within each chain,
          store the indices at which each milk type occurs. For every segment
          of a query path, binary search that type's index list to test whether
          it appears in the segment.

      Gold 3: Moortal Cowmbat
        Techniques: Graphs (Floyd-Warshall), Prefix Sums, Dynamic Programming
        Complexity: O(M^3 + NM)
        Difficulty: Very Hard
        Key Idea:
          - Floyd-Warshall: Direct conversion i -> j may be more expensive than
            converting through intermediate letters. Compute the true minimum
            conversion cost between every pair of letters first.
          - Prefix Sums: For each target letter c, prefix-sum the cost of
            converting each string position into c. This makes the cost of
            converting any substring entirely into c available in O(1).
          - Dynamic Programming: Let dp[i][c] be the minimum cost for a valid
            prefix ending in a block of letter c. Either extend the existing
            c-block by converting the next character to c, or begin a new
            length-K c-block after the best valid prefix ending K positions
            earlier.

    2020 January:
      Bronze 1: Word Processor
        Techniques: Greedy
        Complexity: O(N)
        Difficulty: Trivial
        Key Idea: Process words from left to right. Put each word on the
          current line if it fits within the K-character limit; otherwise start
          a new line. Since words must remain in order, there is never a
          benefit to starting a new line while the next word still fits.

      Bronze 2: Photoshoot
        Techniques: Brute Force (Candidate Enumeration)
        Complexity: O(N^2)
        Difficulty: Easy
        Key Idea: Try possible values of a[0] from smallest to largest. Once
          a[0] is chosen, every later value is forced by
          a[i + 1] = b[i] - a[i]. Reconstruct the entire sequence and reject a
          candidate if any value is outside [1, N] or has already appeared.
          The first valid reconstruction is lexicographically smallest.

      Bronze 3: Race
        Techniques: Binary Search (Last True)
        Complexity: O(N log K)
        Difficulty: Medium
        Key Idea: For a candidate peak speed S, use arithmetic-series sums to
          compute the distance needed to accelerate from 1 up to S and, when
          necessary, decelerate back toward X. If that profile does not already
          reach K, the remaining distance can be traveled at speed S. Feasible
          peak speeds form a monotonic prefix, so binary search for the largest
          feasible S and compute its minimum race time.

      Silver 1: Berry Picking
        Techniques: Brute Force (Candidate Enumeration), Greedy
        Complexity: O(B * (N + K) log N), B <= 1000
        Difficulty: Medium
        Key Idea: Try every possible basket size b that could be the minimum
          size among Elsie's baskets. For a fixed b, greedily split each tree
          into as many full size-b baskets as possible, keeping at most one
          remainder per tree. If there are at least K full baskets, Bessie can
          receive K/2 baskets of size b. Otherwise, after accounting for
          Elsie's K/2 baskets, fill Bessie's remaining baskets with the largest
          remainders. Take the best result over all b.

      Silver 2: Loan Repayment
        Techniques: Binary Search (Last True), Math (Quotient Batching)
        Complexity: O(log N * sqrt(N))
        Difficulty: Medium
        Key Idea: Binary search for the largest X that allows the loan to be
          repaid within K days. In canRepay(X), the daily payment
          Y = floor((N - G) / X) often stays unchanged for many consecutive
          days. Compute how long the current Y remains constant and process
          that entire block at once instead of simulating one day at a time.
          Once Y <= M, the rest can be finished using payments of M directly.

      Silver 3: Wormhole Sort
        Techniques: Binary Search (Last True), Graphs (DSU)
        Complexity: O(log W * (N + M) alpha(N)), plus edge sorting if used
        Difficulty: Hard
        Key Idea: For a candidate minimum wormhole width W, keep only edges
          with width >= W and use DSU to form their connected components. The
          permutation can be sorted iff every position i is connected to the
          position containing the cow that belongs at i. This feasibility
          condition is monotonic as W changes, so binary search for the largest
          W that still allows sorting.

      Gold 1: Time is Mooney
        Techniques: Dynamic Programming (Graph DP)
        Complexity: O(TM)
        Difficulty: Medium
        Key Idea: Let dp[t][v] be the maximum money earned after exactly t days
          while ending at city v. Since every edge takes one day, transition
          from dp[t-1][u] to dp[t][v] across each directed edge u -> v. For
          every t where city 1 is reachable again, evaluate dp[t][1] - C*t^2
          and take the maximum. The quadratic penalty ensures we only need to
          check t up to 1000, which makes this solution feasible.

      Gold 2: Farmer John Solves 3SUM
        Techniques: Prefix Sums (2D), Preprocessing (Frequency Counting)
        Complexity: O(N^2 + Q)
        Difficulty: Very Hard
        Key Idea: First compute how many zero-sum triples have each pair (i, j)
          as their exact leftmost and rightmost indices. Fix i and sweep j to
          the right, maintaining frequencies of values at indices strictly
          between i and j. For each j, the middle value must equal
          -(A[i] + A[j]), so the frequency table gives the number of triples
          with endpoints i and j in O(1). This produces an N x N table where
          count[i][j] contains only triples with exact outer endpoints i and j.
          Convert it into range answers using 2D prefix-style accumulation:
          accumulate over possible left endpoints and right endpoints so that
          count[l][r] becomes the number of triples whose leftmost index is >=
          l and rightmost index is <= r. These are exactly the triples
          completely contained in [l, r], so every query is then O(1).

      Gold 3: Springboards
        Techniques: Sorting, Sweep Line (Event Processing),
          Coordinate Compression, Segment Tree (Range Minimum)
        Complexity: O(P log P)
        Difficulty: Very Hard
        Key Idea: Sweep all springboard endpoints in reverse coordinate order.
          Let dp[i] be the min distance from the end of springboard i to (N,N).
          From a point (x,y), a future springboard with start (sx,sy) can be
          used only if sx >= x and sy >= y. The cost of walking to that
          springboard and then optimally reaching the target is
          (sx - x) + (sy - y) + dp[i] = (dp[i] + sx + sy) - (x + y).
          Therefore, when the reverse sweep reaches a springboard's start,
          insert dp[i] + sx + sy at its y-coordinate. When it reaches a
          springboard's end, query the minimum inserted value among
          y-coordinates >= its y, giving the best reachable next springboard.
          A segment tree over coordinate-compressed y-values supports these
          suffix minimum queries and point updates in O(log P). Also consider
          walking directly from each endpoint to (N,N). Finally, the answer is
          the minimum of walking directly from (0,0) to (N,N) and walking from
          (0,0) to any springboard start followed by its precomputed dp value.

    2020 February:
      Bronze 1: Triangles
        Techniques: Brute Force (Combination Enumeration)
        Complexity: O(N^3)
        Difficulty: Easy
        Key Idea: With N <= 100, enumerate every combination of three points.
          A valid triangle needs two points sharing an x-coordinate and two
          sharing a y-coordinate. For a valid triple, twice its area is the
          horizontal leg length times the vertical leg length, so no division
          by 2 is needed.

      Bronze 2: Breed Flip
        Techniques: Greedy
        Complexity: O(N)
        Difficulty: Easy
        Key Idea: Each maximal contiguous segment where strings A and B differ
          can be fixed with exactly one flip, independently of the other
          mismatch segments. Count how many mismatch segments begin.

      Bronze 3: Swapity Swap
        Techniques: Simulation
        Complexity: O(N * S), where S is the permutation period
        Difficulty: Easy
        Key Idea: Repeatedly apply the two reversals until either K operations
          have been simulated or the entire permutation returns to its starting
          state. Once the arrangement repeats, the process is periodic, so use
          K mod cycleLength to skip complete cycles and simulate only the
          remaining repetitions.

      Silver 1: Swapity Swapity Swap
        Techniques: Functional Graphs, Binary Lifting
        Complexity: O(NM + N log K)
        Difficulty: Medium
        Key Idea: One complete sequence of the M reversals defines a
          permutation f of positions, which can be viewed as a functional
          graph. Precompute jump[j][i] = f^(2^j)(i). Then use the binary
          representation of K to combine power-of-two jumps and find f^K(i)
          for every cow in O(log K) time each.

      Silver 2: Triangles
        Techniques: Sorting, Prefix Sums, Math (Geometry)
        Complexity: O(N log N)
        Difficulty: Hard
        Key Idea: Treat each point (x, y) as the right-angle corner. Its total
          triangle contribution factors as (sum of horizontal distances to
          points with the same y) * (sum of vertical distances to points with
          the same x). Group and sort points by shared x- and y-coordinates.
          For a sorted coordinate list, use prefix sums to compute the total
          distance from a point to all other points on that line in O(1) once
          its index is known (or O(log N) with a lower_bound lookup). Sum the
          product for every point.

      Silver 3: Clock Tree
        Techniques: Trees (Postorder Traversal), Graphs (Bipartite), Invariants
        Complexity: My solution: O(N^2); optimal solution: O(N)
        Difficulty: Easy
        Key Idea:
          - O(N^2) solution: Try every room as the root. Use postorder DFS so
            each child subtree is completely resolved before its parent. After
            fixing a child subtree, make enough parent-child traversals to set
            the child's clock to 12; those traversals also advance the parent's
            clock. After all children are fixed, the root is valid iff its
            remaining clock state can finish correctly.
          - O(N) solution: Every tree is bipartite, so color nodes by depth
            parity from any root. Each move crosses an edge and therefore
            alternates which color class receives a +1 clock update. If the two
            color-class sums are congruent mod 12, every node is a valid start.
            If one side's sum is exactly one greater mod 12, exactly the nodes
            on that side are valid. Otherwise no starting node works. This is a
            useful example of combining bipartite coloring with a modular
            invariant.


CSES:
  Introductory Problems:
    1: Weird Algorithm
      Techniques: Simulation
      Complexity: O(number of generated terms)
      Difficulty: Trivial
      Key Idea: Repeatedly apply the rule from the statement: if n is even,
        replace it with n/2. Otherwise replace it with 3n+1. Output every value
        until reaching 1. Use a 64-bit integer to avoid overflow.

    2: Missing Number
      Techniques: None
      Complexity: O(N)
      Difficulty: Trivial
      Key Idea: Mark every number that appears in the input. Since the values
        are exactly the integers from 1 through N with one missing, the single
        unmarked value is the answer.

    3: Repetitions
      Techniques: Strings (Run / Segment Counting)
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: Scan the string while maintaining the length of the current run
        of equal characters. If the current character matches the previous one,
        extend the run; otherwise reset its length to 1. Track the maximum run
        length seen.

    4: Increasing Array
      Techniques: Greedy
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: Process the array from left to right. If the current value is
        smaller than the previous adjusted value, it must be increased to that
        value; increasing it any further would only add unnecessary cost. Add
        (prev - cur) to the answer whenever cur < prev, then maintain: prev =
        max(prev, cur). This produces the minimum total number of increments
        needed to make the array nondecreasing.

    5: Permutations
      Techniques: Constructive Algorithms
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: Adjacent numbers cannot differ by 1. Numbers of the same parity
        differ by at least 2, so place all even numbers together and all odd
        numbers together. For N >= 4, the boundary between the even and odd
        groups can also be made valid by outputting the evens first and then
        the odds. N = 2 and N = 3 are the only impossible cases.

    6: Number Spiral
      Techniques: Math
      Complexity: O(T)
      Difficulty: Easy
      Key Idea: For any coordinate (y, x), the value lies on the square layer
        k = max(y, x). The diagonal value of that layer is k^2-k+1. From that
        diagonal, move horizontally or vertically by |y-x| positions. Whether
        values increase or decrease depends on the parity of k, so handle the
        cases y >= x and x > y separately using the layer's parity.

    7: Two Knights
      Techniques: Dynamic Programming
      Complexity: O(N)
      Difficulty: Medium
      Key Idea: Let dp[i] be the number of ways to place two knights on an ixi
        chessboard such that they can't attack each other. When moving from i-1
        to i, there are (i-1)(i-1) old squares and 2*i-1 new squares. 3 cases:
        (1) Both knights are on an old square (already computed: dp[i - 1]).
        (2) Both knights are on a new square: Let k = 2*i-1. New placements:
            k * (k - 1) / 2 - 2. Minus 2 to remove the two duplicates.
        (3) One knight on each: For each new square, compute how many old
            squares the other knight could be placed on. Result: (oldSquares -
            2) * 5 + (oldSquares - 3) * 4 + (oldSquares - 4) * (i - 5) * 2.

    8: Two Sets
      Techniques: Constructive Algorithms, Greedy
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: The total sum S is n(n+1)/2. If it is odd, an equal partition
        is impossible. Otherwise, each set should have sum S/2. Process values
        from n to 1. Place i in the first set whenever it does not exceed the
        remaining target. Otherwise place it into the second set.

    9: Bit Strings
      Techniques: Math, Observation
      Complexity: O(N)
      Difficulty: Trivial
      Key Idea: Each of the N positions independently has two choices, so there
        are 2^N bit strings. Compute this value modulo 1e9+7.

    10: Trailing Zeros
      Techniques: Number Theory
      Complexity: O(log_5 N)
      Difficulty: Easy
      Key Idea: Every trailing zero in n! requires a factor of 10 = 2*5. Since
        factorials contain more factors of 2 than 5, the answer is the exponent
        of 5 in n!. Count contributions from multiples of 5, 25, 125, ...:
        floor(n/5) + floor(n/25) + floor(n/125) + ... Each multiple of 25
        contributes an extra factor of 5, each multiple of 125 contributes
        another, and so forth.

    11: Coin Piles
      Techniques: Math (Algebra)
      Complexity: O(T)
      Difficulty: Easy
      Key Idea: First, assume that pile A has fewer coins than pile B. Get both
        piles to have the same number of coins by performing (b-a) operations
        that remove 1 from A and 2 from B. This is only possible if A is at
        least half of B. Once the two piles have the same number of coins, say
        X, they can both be reduced to 0 only if X is divisible by 3. This is
        because performing one operation of each type removes 3 from each pile.
        Therefore, a solution exists if 2 * A >= B and (2 * A - B) % 3 == 0.

    12: Palindrome Reorder
      Techniques: Strings (Character Frequencies), Constructive Algorithms
      Complexity: O(N + A), where A is the number of distinct characters
      Difficulty: Easy
      Key Idea: In a palindrome, every character must occur in mirrored pairs,
        except possibly one character placed in the center. Count each
        character's frequency. If more than one character has an odd count, no
        palindrome is possible. Otherwise, place count/2 copies of each
        character symmetrically at the left and right ends, and place the
        single odd-frequency character in the middle if one exists.


AtCoder:
  Beginner Contest 106:
    A: Garden
      Techniques: Math (Algebra)
      Complexity: O(1)
      Difficulty: Trivial
      Key Idea: The initial area is A*B. The horizontal road removes one unit 
        from A and the vertical road removes one unit from B, so subtract
        (a + b). One single tile was removed twice, so add it back, giving
        a * b - (a + b) + 1. Another way to think of it: The roads remove one
        unit of width and one unit of height from the A-by-B rectangle, so the
        remaining area is (A - 1)(B - 1).

    B: 105
      Techniques: Number Theory (Divisors)
      Complexity: O(N sqrt N)
      Difficulty: Easy
      Key Idea: For each odd number from 1..N, count its positive divisors.
        They come in pairs (d, n/d), so it is enough to test possible divisors
        through sqrt(n). Count the number if it has exactly 8 divisors.

    C: To Infinity
      Techniques: Observation
      Complexity: O(|S|)
      Difficulty: Easy
      Key Idea:
        Leading 1s never change under the transformation. The first digit greater
        than 1 repeatedly expands into an enormous block of copies of itself.
        Therefore, if K lies within the initial run of 1s, the answer is 1;
        otherwise the answer is the first non-1 digit.

    D: AtCoder Express 2
      Techniques: Prefix Sums (2D)
      Complexity: O(N^2 + M + Q)
      Difficulty: Medium
      Key Idea: Build a 2D table where count[l][r] is the number of trains
        whose exact starting and ending stations are l and r. A query [p, q]
        needs every train satisfying p <= l <= r <= q. Accumulate the table
        over both endpoint dimensions so that dp[p][q] becomes the number of
        trains with starting station >= p and ending station <= q. These are
        exactly the trains completely contained within [p, q], allowing every
        query to be answered in O(1).

  Beginner Contest 130:
    A: Rounding
      Techniques: None
      Complexity: O(1)
      Difficulty: Trivial
      Key Idea: Directly follow the condition in the statement: output 0 if
        X < A, otherwise output 10.

    B: Bounding
      Techniques: Prefix Sums
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: The position of each bounce is the sum of all lengths traveled
        so far. Maintain this cumulative distance while reading the input and
        count each bounce whose position is at most X. Include the initial
        bounce at position 0.

    C: Rectangle Cutting
      Techniques: Math (Geometry)
      Complexity: O(1)
      Difficulty: Easy
      Key Idea: Any line passing through the center of a rectangle divides its
        area exactly in half. The given point and the center always determine
        such a line, so the maximum possible smaller area is W*H/2. There are
        multiple optimal cuts only when the given point is itself the center
        (any line containing the center point divides the area evenly). Watch
        out for integer overflow and integer division rounding!

    D: Enough Array
      Techniques: Two Pointers (Sliding Window)
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: Since every array element is positive, increasing the right
        endpoint can only increase the window sum. For each left endpoint,
        advance the right pointer until the sum first becomes at least K. If
        [l, r] is the shortest valid range beginning at l, then every range
        [l, r'], where r' >= r, is also valid. Count all of those at once, then
        remove A[l] and move to the next left endpoint.

    E: Common Subsequence
      Techniques: Dynamic Programming, Prefix Sums (2D)
      Complexity: O(NM)
      Difficulty: Very Hard
      Key Idea: Let dp[i][j] be the number of equal pairs of subsequences that
        can be formed using the first i elements of S and the first j elements
        of T (including the empty subsequence). Consider combining dp[i-1][j]
        and dp[i][j-1]. Normally their overlap, dp[i-1][j-1], is counted twice
        and must be subtracted. However, when S[i] == T[j], every common
        subsequence represented by that overlap also creates one new common
        subsequence pair by appending S[i] and T[j]. Those new pairs exactly
        replace the overlap that would otherwise be subtracted. Therefore:
        if S[i] == T[j]: dp[i][j] = dp[i-1][j] + dp[i][j-1]
        otherwise: dp[i][j] = dp[i-1][j] + dp[i][j-1] - dp[i-1][j-1]
        Initialize dp[i][0] = dp[0][j] = 1 for the empty subsequence.

    F: Minimum Bounding Box
      Techniques: Math (Piecewise Linear Functions), Math (Geometry),
        Brute Force (Candidate Enumeration)
      Complexity: O(N log N)
      Difficulty: Hard
      Key Idea: For each direction, only the extreme initial coordinates can
        ever define xmin, xmax, ymin, or ymax. Each possible boundary position
        is therefore a linear function of time with slope -1, 0, or +1. The
        four bounding-box boundaries are minima or maxima of these linear
        functions, so they are piecewise linear. The width and height are also
        piecewise linear, and between two times where the controlling boundary
        changes, the bounding-box area reaches its minimum at an endpoint.
        Enumerate every nonnegative critical time at which two candidate
        boundary functions intersect. Also include t = 0. Evaluate the
        bounding-box area at every such time and take the minimum.

  Beginner Contest 154:
    A: Remaining Balls
      Techniques: None
      Complexity: O(1)
      Difficulty: Trivial
      Key Idea: Determine which string U matches and decrement the
        corresponding count by one.

    B: I Miss You
      Techniques: None
      Complexity: O(|S|)
      Difficulty: Trivial
      Key Idea: Output exactly |S| copies of the character 'x'.

    C: Distinct or Not
      Techniques: Sorting
      Complexity: O(N log N)
      Difficulty: Easy
      Key Idea: Sort the sequence. If any value occurs more than once, two
        equal values will be next to each other after sorting. Scan adjacent
        pairs and output NO if any pair is equal. Otherwise output YES.

    D: Dice in Line
      Techniques: Math (Expected Value), Sliding Window
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: A fair die with faces 1 through P has expected value
        (P + 1) / 2. The expected sum of K consecutive dice is the sum of their
        individual expected values. Convert each die to its expected value, ]
        compute the sum of the first K, then slide the fixed-length window
        across the array by adding the new value and removing the value that
        leaves. Take the maximum window sum.

    E: Almost Everywhere Zero
      Techniques: Dynamic Programming (Digit DP)
      Complexity: O(|N|)
      Difficulty: Hard
      Key Idea: Precompute how many L-digit strings contain exactly 1, 2, or 3
        nonzero digits. To count valid integers at most N, first count all
        valid numbers with fewer effective leading digits, then follow the
        digits of N from left to right. Whenever a nonzero digit of N is
        encountered, count choices that place a smaller digit there and freely
        choose the required remaining nonzero digits in the suffix. Since K <=
        3, the general digit-DP state can be expanded into explicit formulas
        for one, two, and three nonzero digits.

    F: Many Many Paths
      Techniques: Number Theory (Pascal's Triangle)
      Complexity: O(MAX + (R2 - R1 + 1))
      Difficulty: Hard
      Key Idea: The number of paths from (0,0) to (r,c) is f(r,c) = C(r+c, r).
        For a fixed row r, use the hockey-stick identity to sum all columns at
        once: sum from c=c1..c2 of C(r+c, r) = C(r+c2+1, r+1) - C(r+c1, r+1).
        Precompute factorials and inverse factorials so every binomial
        coefficient can be evaluated in O(1), then sum this expression over all
        rows from R1 through R2.

  Beginner Contest 184:
    A: Determinant
      Techniques: None
      Complexity: O(1)
      Difficulty: Trivial
      Key Idea: Simply print the determinant ad-bc.

    B: Quizzes
      Techniques: Simulation
      Complexity: O(N)
      Difficulty: Trivial
      Key Idea: Process the quiz results from left to right. A correct answer
        increases the score by 1. An incorrect answer decreases it by 1 only
        when the current score is positive.

    AtCoder ABC 184 C: Super Ryuma
      Techniques: Math (Geometry)
      Complexity: O(1)
      Difficulty: Medium
      Key Idea: The maximum number of moves needed to reach another any other
        point is 3. In two moves you can reach any point with the same parity,
        and one additional move can be used to reach all other points. The
        answer is 0 if the start and goal are equal and 1 if they share a
        diagonal or have Manhattan distance at most 3. If the start and end are
        a Manhattan distance of 6 or less, or if a move along a diagonal brings
        you to a goal diagonal or within 3 of the goal, the answer is 2.
        Otherwise, the answer is 3.

    D: increment of coins
      Techniques: Dynamic Programming (Expected Value DP)
      Complexity: O(ABC)
      Difficulty: Medium
      Key Idea: Let dp[i][j][k] be the expected number of operations remaining
        when the three piles have i, j, and k coins. From state (i,j,k), the
        next state is (i+1,j,k) with probability i/(i+j+k), (i,j+1,k) with
        probability j/(i+j+k), and (i,j,k+1) with probability k/(i+j+k).
        Therefore: dp[i][j][k] = 1 + i/(i+j+k) * dp[i+1][j][k] + j/(i+j+k) *
        dp[i][j+1][k] + k/(i+j+k) * dp[i][j][k+1]. Any state where one pile has
        reached 100 is terminal and has expected remaining cost 0. Compute the
        states in decreasing order so every dependent state is already known.

    E: Third Avenue
      Techniques: Graphs (BFS)
      Complexity: O(HW)
      Difficulty: Medium
      Key Idea: Treat every traversable grid cell as a graph vertex. Moving to
        an adjacent non-wall cell costs 1, and teleporting between two cells
        with the same letter also costs 1, so BFS gives the shortest path. The
        first time BFS processes a cell with letter c, enqueue every other
        cell with that letter. After that, never expand letter c again.

    F: Programming Contest
      Techniques: Meet-in-the-Middle, Binary Search (Bounds)
      Complexity: O(N * 2^(N/2))
      Difficulty: Hard
      Key Idea:
        Enumerating all 2^N subsets is too expensive for N <= 40, so split the
        items into two halves.

        Enumerate every subset sum of the first half and every subset sum of the
        second half. Discard sums greater than T, since all values are positive.

        Sort the subset sums of one half. For each sum s from the other half,
        binary search for the largest value x such that

            s + x <= T.

        Every complete subset is uniquely formed by combining one subset from
        each half, so considering all such best combinations finds the maximum
        achievable sum not exceeding T.

  Beginner Contest 280:
    A: Pawn on a Grid
      Techniques: None
      Complexity: O(HW)
      Difficulty: Trivial
      Key Idea: Scan every cell of the grid and count how many contain '#'.

    B: Inverse Prefix Sum
      Techniques: Prefix Sums
      Complexity: O(N)
      Difficulty: Trivial
      Key Idea: If S[i] is the prefix sum through position i, then: A[0] = S[0]
        A[i] = S[i] - S[i-1]. Recover each original value from the difference
        between consecutive prefix sums.

    C: Extra Character
      Techniques: None
      Complexity: O(|S|)
      Difficulty: Easy
      Key Idea: Compare S and T from left to right. The first position where
        they differ is the location of the inserted character. If all
        characters of S match, then the extra character is at the end of T.

    D: Factorial and Multiple
      Techniques: Number Theory (Prime Factorization)
      Complexity: O(sqrt(K))
      Difficulty: Medium
      Key Idea: Prime-factorize K: K = [p1^a1 * p2^a2 * ...]. For K to divide
        N!, N! must contain at least ai copies of every prime pi. For each
        prime factor p^a, find the smallest N such that the exponent of
        p in N! is at least a. This can be done by visiting multiples of p and
        counting how many copies of p each contributes. Each prime factor gives
        a minimum required N. The final answer is the maximum of these, since
        N! must simultaneously contain enough copies of every prime factor.

    E: Critical Hit
      Techniques: Dynamic Programming (Expected Value DP),
        Math (Modular Inverse)
      Complexity: O(N log MOD)
      Difficulty: Medium
      Key Idea: Let dp[i] be the expected number of attacks needed when the
        monster has i HP remaining. Every attack costs one operation. With
        probability P/100 it deals 2 damage, and otherwise it deals 1 damage,
        giving: dp[i] = 1 + (P/100) * dp[i-2] + (1-P/100) * dp[i-1].  The base
        cases are dp[0] = 0 and dp[1] = 1. Because probabilities must be
        represented modulo 998244353, division by 100 is multiplication by the
        modular inverse 100^(MOD-2).

    AtCoder ABC 280 F: Pay or Receive
      Techniques: Graphs (DSU, DFS),
      Complexity: O((N + M + Q) alpha(N))
      Difficulty: Hard
      Key Idea: Use a DSU to find connected components. If two vertices are in
        different components, the asnwer is "nan". Within each component,
        choose an arbitrary root and use DFS to assign every vertex a cost.
        When traversing an edge e from u to v, cost[v] = cost[u] + e.cost. If
        cost[v] has already been assigned to a different value, then there is
        a cycle with a nonzero score change. Traversing that walk in the
        profitable direction repeatedly allows the score to grow without bound,
        so every query within that component is "inf". If no contradiction
        exists, every path between two vertices has the same total score
        change, so the answer from X to Y is simply cost[Y] - cost[X].

  Educational DP Contest:
    A: Frog 1
      Techniques: Dynamic Programming
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: Let dp[i] be the minimum total cost to reach stone i. The frog
        can reach stone i only from i-1 or i-2, so the optimal way to reach i
        is the cheaper of those two possibilities: dp[i-1] + |h[i] - h[i-1]|,
        dp[i-2] + |h[i] - h[i-2]|. Each state depends only on previously
        computed states, so process the stones from left to right.

    B: Frog 2
      Techniques: Dynamic Programming
      Complexity: O(NK)
      Difficulty: Easy
      Key Idea: Let dp[i] be the minimum cost to reach stone i. The frog may
        jump to i from any of the previous K stones, so try every possible
        previous stone: dp[i] = min{1 <= k <= K}: dp[i-k] + |h[i] - h[i-k]|.
        Every transition comes from an earlier stone, so the states can be
        computed from left to right.

    C: Vacation
      Techniques: Dynamic Programming
      Complexity: O(N)
      Difficulty: Easy
      Key Idea: Let dp[i][a] be the maximum happiness after day i if activity a
        is performed on that day. Since the same activity cannot be performed
        on consecutive days, the previous day must use one of the other two
        activities. Therefore: dp[i][A] = happiness[i][A] + max(dp[i-1][B],
        dp[i-1][C]) with similar transitions for B and C. The answer is the
        maximum of the three possible activities on the final day.

    D: Knapsack 1
      Techniques: Dynamic Programming (0-1 Knapsack)
      Complexity: O(NW)
      Difficulty: Medium
      Key Idea: Let dp[i][w] be the maximum total value obtainable using the
        first i items with total weight at most w. For each item, either do not
        take it: dp[i][w] = dp[i-1][w] or, if it fits, take it: dp[i][w] =
        max(dp[i][w], dp[i-1][w-weight[i]] + value[i]). Since each transition
        uses the previous item layer, every item can be chosen at most once.

    E: Knapsack 2
      Techniques: Dynamic Programming (0/1 Knapsack)
      Complexity: O(NV), where V is the sum of all item values
      Difficulty: Medium
      Key Idea: A normal knapsack DP indexed by weight is impossible because W
        is too large. However, the sum of all item values is small enough to
        use as the DP dimension instead. Let dp[i][v] be the minimum total
        weight needed to obtain exactly value v using the first i items. For
        each item, either skip it or take it: dp[i][v] = min(dp[i-1][v],
        dp[i-1][v-value[i]] + weight[i]). After processing all items, the
        answer is the largest value v whose minimum required weight is at most
        W. This is the same 0/1 knapsack structure as Knapsack 1, but the state
        is inverted from "maximum value for each weight" to "minimum weight for
        each value" because the value dimension has the manageable bound.

    F: LCS
      Techniques: Dynamic Programming
      Complexity: O(NM)
      Difficulty: Medium
      Key Idea: Let dp[i][j] be the length of the longest common subsequence of
        the first i characters of S and the first j characters of T. If S[i-1]
        == T[j-1], those matching characters can extend an optimal LCS
        of the previous prefixes: dp[i][j] = dp[i-1][j-1] + 1. Otherwise, at
        least one of the two final characters is not used: dp[i][j] =
        max(dp[i-1][j], dp[i][j-1]). After computing the table, walk backward
        from dp[N][M]. If the value came from a diagonal transition, that
        character belongs to the LCS; otherwise move to a neighboring state
        with the same optimal value.

    G: Longest Path
      Techniques: Graphs (Topological Sort), Dynamic Programming (Graph DP)
      Complexity: O(N + M)
      Difficulty: Medium
      Key Idea: In a DAG, every edge goes from an earlier vertex to a later
        vertex in some topological ordering. Let dp[v] be the length of the
        longest path ending at v. Process vertices in topological order, and
        for every edge v -> u: dp[u] = max(dp[u], dp[v] + 1). Because all
        predecessors of v have already been processed when v is reached, dp[v]
        is final. The answer is the maximum dp value over all vertices.

    H: Grid 1
      Techniques: Dynamic Programming (Grid DP)
      Complexity: O(HW)
      Difficulty: Easy
      Key Idea: Let dp[i][j] be the number of valid paths from the top-left
        corner to cell (i,j). If the cell is blocked, dp[i][j] = 0. Otherwise,
        the only possible final move comes from above or from the left:
        dp[i][j] = dp[i-1][j] + dp[i][j-1]. Take all counts modulo 1e9+7.

    I: Coins
      Techniques: Dynamic Programming
      Complexity: O(N^2)
      Difficulty: Medium
      Key Idea: Let dp[i][j] be the probability that exactly j of the first i
        coins land heads. For coin i, state (i,j) can be reached in two ways:
        coin i is tails: dp[i-1][j] * (1 - p[i]), or coin i is heads:
        dp[i-1][j-1] * p[i]. dp[i][j] is the sum of these values. After
        processing all coins, sum dp[N][j] for every j > N/2.

    J: Sushi
      Techniques: Dynamic Programming (Expected Value DP)
      Complexity: O(N^3)
      Difficulty: Hard
      Key Idea: The exact identities of the plates do not matter. A state can
        be described only by: (i, j, k), the number of plates with 1, 2 and 3
        sushi, respectively. Let E(i,j,k) be the expected number of operations
        remaining. There are t = i+j+k nonempty plates. Choosing an empty plate
        leaves the state unchanged, which creates a self-transition in the
        expectation equation: E = 1 + (N-t)/N * E + i/N * E(i-1,j,k) + j/N *
        E(i+1,j-1,k) + k/N * E(i,j+1,k-1). Rearranging to remove the self-
        transition gives: E = N/t + i/t * E(i-1,j,k) + j/t * E(i+1,j-1,k)
        + k/t * E(i,j+1,k-1). Memoize each (i,j,k) state. E(0,0,0) is 0.
